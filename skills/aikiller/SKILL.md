# aikiller — 한국어 AI 문체 검사 + 다듬기

**이 스킬의 핵심 원칙: 규칙으로 되는 일을 LLM에게 시키지 마라.**

이 저장소에는 결정적 엔진이 있다. 패턴 탐지·점수 계산·안전한 치환은 전부
코드가 한다. 그쪽이 재현 가능하고, 빠르고, 의미를 바꾸지 않는다.
너(모델)는 **코드가 못 고치는 것만** 맡는다.

CLI 는 `${CLAUDE_PLUGIN_ROOT}/skills/aikiller/run.sh` 로 부른다. 설치 방식과
무관하게 저장소를 찾아 준다. 아래에서는 `RUN` 으로 줄여 쓴다.

---

## Phase 1 — 검사

먼저 상태를 잰다. 파일이면 경로를, 붙여넣은 글이면 임시 파일에 쓰고 경로를 준다.

```bash
RUN detect <파일경로> --genre <essay|report|column|blog|abstract> --json
```

장르는 첫 300자로 판단한다. 모르겠으면 `essay`. **장르를 잘못 고르면 오탐이
난다** — 보고서·논문·공문은 반드시 `report`, 칼럼·기사는 `column`.

JSON 에서 읽을 것:

| 필드 | 뜻 |
|---|---|
| `score` `band` | 0~100 점수와 등급(low/medium/high) |
| `confidence` | `insufficient` 면 **판정하지 말고 그대로 보고한다** |
| `signals[]` | 근거. `layer`(L1~L4) · `label` · `detail` · `calibrated` |
| `sentences[]` | 문장별 점수와 걸린 패턴 ID |
| `fusion_calibrated` | `false` 면 점수는 상대 비교용이라고 반드시 밝힌다 |
| `notes[]` | 경고. 사용자에게 그대로 전달한다 |

**사용자가 "검사만" 요청했으면 여기서 멈춘다.** 다듬지 마라.

---

## Phase 2 — 규칙 다듬기

사용자가 수정을 원할 때만 진행한다.

```bash
RUN humanize <파일경로> --level <safe|moderate|aggressive> --genre <장르> --json
```

강도는 사용자가 지정하지 않았으면 `moderate`. 지정어 매핑:

| 사용자 말 | level |
|---|---|
| "살짝만", "최소한만", "확실한 것만" | `safe` |
| (지정 없음) | `moderate` |
| "강하게", "많이", "확 바꿔" | `aggressive` |

반환값에서 `changes[]`(적용된 규칙), `change_rate`, `before_layers` /
`after_layers` 를 챙긴다. `aborted: true` 면 변경률이 50%를 넘어 원문을
돌려준 것이다 — 그대로 보고하고 강도를 낮춰 다시 시도한다.

---

## Phase 3 — LLM 보정 (규칙이 못 고치는 것만)

Phase 2 의 결과를 다시 검사해서 남은 게 있는지 본다.

```bash
RUN prompt <Phase2_결과파일> --genre <장르>
```

이 명령이 **지적된 구간과 처방이 박힌 프롬프트**를 만들어 준다. 그 지적
사항만 고친다. 주로 이런 것들이다.

- **무생물 주어** — "이 연구는 ~을 보여준다" → "이 연구에서 ~가 드러났다"
- **문단 리듬** — 문장 길이가 균일하다. 단문 1~2개와 장문 1개를 섞는다.
  단, **인접 문장을 잇기만 하고 없던 내용을 넣지 않는다.**
- **문두 접속부사 반복** — 절반 이상 지워도 논리는 유지된다.
- **기계적 병렬** — "첫째/둘째/셋째"를 문장 흐름으로 녹인다.

### 절대 규칙

1. **사실·수치·고유명사·직접 인용은 100% 보존한다.** 하나라도 바꾸면 실패다.
2. **없던 주장을 만들지 않는다. 있던 주장을 지우지 않는다.**
3. **경어법과 장르를 유지한다.** `습니다`체를 반말로 떨어뜨리지 마라.
4. **지적되지 않은 문장은 건드리지 마라.**
5. **AI 상투구를 새로 심지 마라.** 결말을 다듬는다고 "결국", "~하는 이유다",
   "~로 이어진다"를 새로 만들어 넣는 건 자기모순이다. 이건 실제로 관측된
   실패 유형이다.

---

## Phase 4 — 검증

고친 글을 다시 검사해서 실제로 나아졌는지 확인한다.

```bash
RUN detect <최종파일> --genre <장르> --json
```

점수가 **올랐으면** Phase 3 에서 뭔가 잘못한 것이다. 무엇이 새로 걸렸는지
`signals` 로 확인하고 그 부분을 되돌린다.

---

## 출력 형식

한 번에 다음을 낸다. 장황하게 쓰지 마라.

```
검사 결과 — {score}/100 ({등급}) · {n_chars}자 · 장르 {genre}
```

1. **근거 3~5개** — `signals` 상위에서. `[L1 실측]` / `[L2 추정]` 배지를 살린다.
2. **점수가 높은 문장 3개** — 문장과 걸린 패턴 이름
3. 수정을 했으면: **최종 본문** + `점수 {before} → {after}` + 적용 규칙 목록
4. `notes[]` 의 경고를 그대로 전달

### 반드시 붙이는 말

- `fusion_calibrated: false` 면 → "가중치가 아직 실측 피팅되지 않아 점수는
  상대 비교용입니다."
- `confidence: insufficient` 면 → 점수를 말하지 말고 "150자 미만은 어떤
  탐지기도 신뢰할 수 없습니다"라고만 한다.
- 사용자가 판정 근거로 쓰려는 낌새가 보이면 → "징계·평가·채용의 단독
  근거로 쓰지 마세요."

## 하지 말아야 할 것

- **패턴을 머릿속으로 다시 탐지하지 마라.** `detect` 가 이미 했다. 모델이
  눈대중으로 다시 세면 숫자가 흔들리고 재현이 안 된다.
- **규칙이 이미 고친 걸 또 고치지 마라.** Phase 2 결과를 그대로 받아라.
- **"AI가 썼다"고 단정하지 마라.** 이 도구는 AI 문체 지표를 낼 뿐이다.
- **점수를 반올림해 부풀리지 마라.** JSON 값 그대로 쓴다.
- 장르를 안 물어보고 `essay` 로 밀어붙이지 마라 — 격식체 오탐의 주된 원인이다.
