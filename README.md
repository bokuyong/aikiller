# ai킬러 — 한국어 AI 문체 탐지 + 다듬기

탐지기와 다듬기를 **하나의 패턴 레지스트리** 위에 올린 도구입니다.
같은 규칙이 "이게 AI 티다"라고 짚고, 그대로 "이렇게 고쳐라"가 됩니다.

```
                    ┌──────────────────────┐
   문서 ──파서──▶   │  patterns.py (SSOT)  │
 (hwp/hwpx/         │  74개 패턴 · 10 카테고리 │
  docx/pdf/txt)     └──────────┬───────────┘
                       ┌───────┴────────┐
                       ▼                ▼
                  detect.py         humanize.py
                 AI 문체 점수        규칙 다듬기
                 + 문장 히트맵       + LLM 프롬프트
                       └───────┬────────┘
                               ▼
                    CLI · 웹 UI · JSON API
```

의존성 없이 표준 라이브러리만으로 돕니다 (PDF만 선택적으로 `pypdf`).

## 설치

### 명령줄 도구로

```bash
./install.sh
```

`~/.local/bin/aikiller` 런처 하나만 만듭니다. 파이썬 패키지를 설치하지 않으므로
저장소를 고치면 즉시 반영됩니다. 제거는 `./install.sh --uninstall`.

Python 3.9 이상이면 됩니다 (macOS 기본 python3 포함).

### Claude Code 스킬로

```
/plugin marketplace add bokuyong/aikiller
/plugin install aikiller@aikiller
```

새 세션에서 `/aikiller` 또는 자연어로 "이 글 AI 티 검사해줘".

대화 중에 검사·다듬기를 시킬 수 있습니다. 스킬은 **규칙 엔진을 먼저 돌리고**
(결정적·재현 가능) 규칙이 못 고치는 것만 모델이 손봅니다 — 무생물 주어,
문단 리듬, 문두 접속사 같은 것들입니다. 절차는 [SKILL.md](skills/aikiller/SKILL.md)에
있습니다.

## 탐지 원리 — 4개 증거 계층

| 계층 | 내용 | 캘리브레이션 |
|---|---|---|
| **L1** 통계 지표 | 쉼표 계열 4종 (포함률·밀도·연결어미 뒤·구간 길이) | ✅ **실측 기준선** — 아래 참조 |
| **L2** 패턴 밀도 | 74개 AI 티 패턴을 1,000자당 가중 밀도로 환산 | ⚠️ 가중치 추정 |
| **L3** 리듬 | 문장 길이 변동계수, 종결어미 다양성, 장문 부재 | ⚠️ 휴리스틱 임계값 |
| **L4** 사람 증거 | 자기 개입·시점 앵커·구어체 등 7종 (**점수를 깎음**) | ⚠️ 가중치 추정 |

네 계층을 로지스틱으로 융합해 0~100점을 냅니다. L1은 사실상 쉼표 하나의
현상이라, 쉼표가 많으면 AI 증거로 세되 적다고 해서 사람 증거로 크게 세지는
않도록 음수 쪽에 하한(-0.5)을 뒀습니다.

### 패턴 레지스트리 (74개)

| 카테고리 | 개수 | 대표 패턴 |
|---|---|---|
| A 번역투 | 20 | 이중피동, '~를 통해', '가지고 있다', '-들' 남용, 무생물 주어 |
| B 영어 과다 | 2 | 괄호 병기, '~라고 알려진' |
| C 구조 | 10 | **부정대구 'A가 아니라 B'**, 대구 'A인가 B인가', 연결어미 뒤 쉼표 |
| D AI 관용구 | 22 | **분열문 '필요한 것은 X이다'**, '~로 이어진다', '~하는 이유다' |
| F 수식·중복 | 4 | 정도부사, '~적 N' 체인, 범용 정책동사 |
| G hedging | 4 | 다중 완곡, 안전 균형 lexicon |
| H 접속사 | 4 | 문두 접속사, '이는~' 반복, '즉' 남발 |
| I 형식명사 | 5 | '것이다' 종결, '~할 필요가 있다' |
| J 시각 장식 | 3 | 대시 남용, 괄호 부연 |
| E 리듬 | (L3) | 문장 길이 변동계수, **장문(100자+) 부재**, 종결어미 다양성 |

굵은 항목은 **사람 코퍼스 실측에서 0건 또는 10배 이상 차이**가 확인된 신호입니다.
각 패턴의 `evidence` 필드에 근거를 적어 뒀습니다. `GET /api/patterns`로도 볼 수 있습니다.

오탐을 막는 두 장치가 붙어 있습니다.
- `min_count` — 사람도 한두 번은 쓰는 표현은 N회 이상일 때만 신호로 셉니다.
- `context` — 위치·문맥 조건. 예: D-11 시간지평은 **문두 + 후반 30%**에서만 발화합니다
  (그 조건에서 사람 0건 vs AI 12건/12편).

**가장 강한 단일 신호는 부정대구입니다** — "A가 아니라 B다". AI 5.8 vs 인간 0.6
(9.2배, G²=41.7, p<0.0001), 사람 24편에서 0건. 사람 다용자가 실재해서 2회부터
셉니다.

연결어미 뒤 쉼표("~하며, ~한다")도 강한 신호지만(인간 4.10% vs AI 19.83%),
'고'는 사고·광고·냉장고 같은 명사 말음절과 구별할 수 없어 자동 치환에서 뺐습니다.

## 지금 상태에서 믿을 수 있는 것 / 없는 것

솔직하게 적습니다. 이 항목이 이 프로젝트의 신뢰도 그 자체입니다.

**믿을 수 있음**
- L1 계층은 실측 기준선을 씁니다. 사람/AI 극값의 출처는 [baselines.py](aikiller/baselines.py)에
  적어 뒀습니다 — 한국어 AI 텍스트 판별 연구 KatFish(Park et al., 사람 470편 vs
  LLM 1,624편)의 보고 수치입니다.
- **장르에 따라 지표가 뒤집히면 그 지표를 아예 뺍니다.** 예를 들어 보고서체에서는
  쉼표 포함률의 사람 내 분산(±18.3)이 사람·AI 극간 거리(5.4)보다 커서 판별이
  성립하지 않습니다. 그런 셀은 `None`으로 비워 두고 계산에서 제외합니다.
- 규칙 다듬기는 결정적이고 문법적입니다. 사실·수치·인용을 만들거나 지우지 않습니다.
- 150자 미만은 점수를 내지 않고 `판정 불가`를 반환합니다.

### 현재 분리도 (2026-08, 레지스터 9종 수동 표본)

| 레지스터 | 점수 | | 레지스터 | 점수 |
|---|---|---|---|---|
| 개인 블로그 | 6.6 | | 학술 논문 | 9.4 |
| 신문 기사 | 7.8 | | 문학 에세이 | 9.8 |
| 기술 문서 | 8.7 | | 법률 문서 | 10.0 |
| | | | 관공서 공문 | 10.1 |
| **AI 칼럼** | **39.8** | | **AI 에세이** | **84.8** |

사람 글 6.6~10.1 / AI 글 39.8~84.8. 표본이 9건뿐이라 통계적 주장은 아닙니다.

**아직 믿으면 안 됨**
- **융합 가중치가 실측 피팅되지 않았습니다.** `fusion_calibrated: false`가 항상 노출됩니다.
  `scripts/calibrate.py`를 돌리기 전까지 점수는 **상대 비교용**이고,
  등급 경계(25/60)도 위 9건 표본에 맞춘 잠정값입니다.
- L3 기준선(`baseline_v2.json`)은 전 셀이 `_placeholder: true`입니다.
- `evidence` 필드가 없는 패턴이 다수입니다. 그 가중치는 추정치입니다.

**관측된 부작용 하나**
- 다듬은 뒤 **L3 리듬이 오히려 나빠집니다**. 완충 표현과 접속부사를 걷어내면
  문장 길이가 더 균일해지기 때문입니다. 규칙 다듬기의 구조적 한계이고,
  문단 리듬은 `prompt` 명령의 LLM 경로에서 손봐야 합니다.

### 검수에서 고친 것 (2026-08)

4개 축(정규식 정확성 · 탐지 방법론 · 보안 · 한국어 언어학)으로 검수를 돌려
아래를 고쳤습니다. 전부 회귀 테스트로 고정돼 있습니다.

**사람 글을 실제로 망가뜨리던 것들**

| 증상 | 원인 |
|---|---|
| `전쟁으로 인해` → `전쟁으 때문에` | 탐욕적 수량자가 '으로'의 '으'를 먹음 |
| `여러 문제들이었다` → `여러 문제가었다` | 계사 '이-'를 주격조사로 오인 |
| `사고, 화재, 침수` → `사고 화재, 침수` | '고'로 끝나는 명사를 연결어미로 오인 |
| `여겨집니다` → `보인다` | 고정 문자열 치환이 경어법을 깸 |
| `혁신이라고 할 수 있습니다` → `혁신이입니다` | 계사 중복 |
| `이를 요약하면,` → `이를` | 문중 삭제로 목적어가 붕 뜸 |
| `평점 ★★★☆☆` → 통째로 삭제 | 이모지 범위에 일반 기호가 섞임 |

**오탐 (검수 전 → 후)**

학술 논문 **98.6 → 9.4**, 관공서 공문 **94.5 → 10.1**, 기술 문서 **90.8 → 8.7**,
신문 기사 **85.9 → 7.8**. 원인은 세 가지였습니다.

1. `lexical_diversity` 지표가 극값(0.65/0.55) 하드코딩 탓에 **항상 클립 천장에
   붙는 상수**였고, 게다가 `ai < human`이라 **부호까지 반대**였습니다. 사람 글
   점수를 통째로 끌어올리고 있었습니다. `hanja_nominalizer_density`도 같은 문제라
   둘 다 L1에서 제외했습니다.
2. 실측이 **역전된** 패턴(사람이 더 많이 쓰는 표현)이 양의 가중치를 갖고
   있었습니다 — `A-16` 대명사는 사람이 8배 더 쓰는데 가중치 0.9였습니다.
   `A-1`·`A-2`·`A-11`·`A-16`·`I-1` 전부 0.4 이하로 내렸습니다.
3. **"AI라는 증거"만 모으고 "사람이라는 증거"는 세지 않았습니다.**
   역방향 지표(L4)를 추가했습니다 — 아래 참조.

**신호 정합성**
- `A-20`이 원 분류 체계의 **대조군**(능동 진행 `~하고 있다`, 격차 없음)을 잡고
  **신호**(피동 진행 `~되고 있다`)를 놓치고 있었습니다. 뒤집었습니다.
- 최강 신호인 **부정대구 `A가 아니라 B`**(9.2배, p<0.0001)가 미구현이었습니다.
  `C-8b`로 추가했습니다.
- L2 점수 곡선이 지수 포화라 증거를 75% 지워도 값이 19%밖에 안 움직였습니다.
  선형으로 바꿨습니다.

**보안** — 697KB 업로드가 700MB로 부푸는 **zip 폭탄**과 HWP **zlib 폭탄**으로
서버를 OOM 시킬 수 있었습니다. 압축 해제 크기·압축비 상한을 걸었습니다.
그 외 keep-alive 요청 desync, slowloris(타임아웃 없음), 동시성 무제한을 고쳤습니다.

### 역방향 지표 (L4) — 사람 글의 증거

오탐 대책 중 투입 대비 효과가 가장 큽니다. 원 분류 체계 실측에서
**AI 코퍼스 0건 또는 사람 우세**로 관측된 것들입니다.

| ID | 신호 | 근거 |
|---|---|---|
| HS-1 | 화자 자기 개입 ("솔직히", "잘 모르겠") | 사람 13건/11편 vs AI 99편 **0건** |
| HS-2 | 시점 앵커 ("당시", "그때", "작년") | '당시' 사람 10건/9편 vs AI **0건** |
| HS-3 | 고충·정서 어휘 ("힘들었다", "막막") | '힘들다' 사람 5건 vs AI **0건** |
| HS-4 | 문두 "또," | **사람 전용** — AI는 "또한"만 씀 |
| HS-5 | 수혜 보조동사 ("~해 줬다") | 사람 우세 |
| HS-6 | 구어체 축약 ("근데", "되게") | — |
| HS-7 | 1인칭 서술 ("나는", "내가") | — |

**원리적으로 불가능**
- 짧은 글 판정. 신호가 물리적으로 부족합니다.
- 패러프레이즈·휴머나이저 통과본. 이 저장소의 `humanize` 명령이 곧
  자기 자신에 대한 공격입니다. `scripts/eval.py`가 그 하락폭을 측정합니다.

> 이 도구는 "AI가 썼다"를 단정하지 않습니다. **AI 문체 지표 점수와 근거**를 냅니다.
> 징계·평가·채용의 단독 근거로 쓰지 마세요.

## 다듬기 강도

| 등급 | 무엇을 하나 | 예 |
|---|---|---|
| `safe` | 문법적으로 의미 불변이 보장되는 것만 | 되어진다 → 된다 · ~하며, → ~하며 |
| `moderate` (기본) | 거의 항상 안전. 드물게 문맥 예외 | ~라고 할 수 있다 → ~다 · 심화되고 있다 → 심화된다 |
| `aggressive` | 문체를 실제로 바꿈 | 매우 삭제 · 많은 사람들이 → 많은 사람이 · "급변하는 현대사회" 서두 삭제 |

**안전장치 4개**
1. 코드블록·인라인코드·직접인용·URL·인용블록은 마스킹 후 복원 — 절대 수정 안 함
2. risk 등급별 적용 범위 제한
3. 변경률 30% 경고 / 50% 초과 시 중단하고 원문 반환
4. 경어법 유지 — `습니다`체를 반말로 떨어뜨리지 않음

규칙으로 못 고치는 것(무생물 주어, 문단 리듬, 문두 접속부사)은
`prompt` 명령이 **탐지 근거가 박힌 LLM 다듬기 프롬프트**를 만들어 줍니다.


`scripts/corpus.py`가 이 셋을 다 만들어 줍니다.

- `wiki` — 위키백과 덤프를 스트리밍 파싱해 위키문법을 걷어내고 산문만 추출합니다.
  덤프 파일명의 날짜가 2022-11 이후면 거부합니다(`--force`로만 통과).
- `generate` — 사람 코퍼스의 첫 문장에서 주제를 뽑아 **주제를 맞춘** AI 글을 만듭니다.
  주제가 안 맞으면 탐지기가 문체가 아니라 주제를 배웁니다. 프롬프트 5종·온도 4종을
  섞습니다. `--provider anthropic|openai`, 모델은 `--model`로 바꿔서 여러 번 돌리세요.
- `adversarial` — 자기 자신의 다듬기 기능으로 AI 코퍼스를 통과시켜 **방패 통과본**을 만듭니다.
- `import` — 로컬 hwp/docx/pdf를 코퍼스로 넣습니다. `human` 라벨에는
  `--attest-pre-2022` 플래그를 강제합니다.

파일명에 장르를 넣으면 장르별로 분리 집계합니다: `report__001.txt`

```bash
python3 scripts/calibrate.py
```

클래스당 최소 20건이 없으면 거부합니다. 적은 데이터로 피팅하면
과적합된 가중치가 "실측"으로 둔갑하기 때문입니다.

```bash
python3 scripts/eval.py
```

`accuracy`가 아니라 **`TPR @ FPR=1%`** 를 봅니다 — 사람 글 100건 중 1건만
오탐하는 지점에서 AI 글을 몇 % 잡는가. 상용 도구들이 광고하는 "정확도 98%"는
자체 테스트셋 기준이라 실사용 성능을 말해 주지 않습니다.

길이 구간별·장르별·적대적으로 쪼개서 봅니다. 적대적 하락폭이 이 사업의

### JSON API

```
GET  /                                       -> 랜딩 페이지
GET  /app                                    -> 도구 화면
POST /api/detect      {text, genre}          -> 리포트 (점수·근거·문장별 점수)
POST /api/humanize    {text, level, genre}   -> 다듬기 결과 + 계층 델타
POST /api/parse       {filename, data_b64}   -> 문서에서 텍스트 추출
GET  /api/patterns                           -> 패턴 레지스트리 전체
GET  /api/history                            -> 로컬 분석 기록
```

관점에서 이 설계를 유지하는 편이 안전합니다.
